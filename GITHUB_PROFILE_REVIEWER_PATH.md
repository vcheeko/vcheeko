# GitHub Profile — Reviewer Path

This document defines the intended first-minute path through the public portfolio.

## First 30 seconds

A reviewer should understand three things immediately:

1. **Positioning:** AI systems & product builder, not claimed senior SWE.
2. **Main system:** KORA — governed, evidence-driven AI/tool orchestration.
3. **Proof surface:** public verifier/evidence harness plus two implemented product/code projects.

## Recommended pinned repository order

GitHub pin settings are profile metadata and are not changed by this repository. The recommended order is:

1. **vcheeko** — profile + KORA public evidence surface
2. **the-first-second** — compact code/testing/CI signal
3. **tri-glav-website** — shipped product/UX/static engineering signal
4. **nexts-interplanetary-ledger** — systems-thinking concept, only after the implemented projects

If additional public KORA runtime repositories become available, the reproducible KORA Golden Demo should replace NEXST in the first four.

## What each pin should prove

### vcheeko

Proves: product/system framing, conservative claims, evidence discipline, KORA architecture.

### the-first-second

Proves: code extraction, deterministic mechanics, automated tests, CI, iterative PR discipline.

### tri-glav-website

Proves: public product delivery, responsive frontend implementation, quality checks, deployment-oriented work.

### NEXST

Proves: speculative systems analysis and ability to narrow an ambitious idea into testable questions. It should not be used as the primary engineering proof because it is currently concept-only.

## Reviewer conversion target

The desired first-minute reaction is:

> "This is not a conventional junior portfolio. The strongest claim is systems/product thinking; there is enough public engineering evidence to justify a technical conversation, and the claims are deliberately narrower than the ambition."

## What should not dominate the profile

- large lists of unfinished ideas;
- claims without an evidence link;
- private-runtime details that cannot be publicly checked;
- concept repositories ahead of implemented/tested repositories;
- stale draft PRs or abandoned work without an explicit historical status.

## Next promotion rule

Do not add a new project to the top three merely because it is ambitious. Promote it only when it offers a stronger externally verifiable signal than one of the current top three.
